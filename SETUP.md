# Setup

How this profile repository works, and what has to be configured once.

## What runs here

| Workflow | Trigger | What it does |
| --- | --- | --- |
| [`quality.yml`](.github/workflows/quality.yml) | push, PR, weekly | Lints Markdown, verifies every link resolves, checks the four READMEs are in sync |
| [`snake.yml`](.github/workflows/snake.yml) | manual (opt-in) | Generates the contribution-graph snake animation |

The READMEs themselves are generated by
[`gen_readme.py`](.github/scripts/gen_readme.py) — see *Editing the README* below.

Dependabot ([`dependabot.yml`](.github/dependabot.yml)) opens a monthly PR when a
pinned action needs bumping.

## Configuration

The quality checks use the built-in `GITHUB_TOKEN`; no personal access token
or write permission is needed for them. The optional, manually triggered snake
workflow declares its own write permission.

## Editing the README

The four READMEs are **generated** from a single source of truth:
[`.github/scripts/gen_readme.py`](.github/scripts/gen_readme.py). Education, practical skills, stack badges,
the Selected work table and the experience bullets all live there, so a change
gets applied to all four languages at once:

```bash
python .github/scripts/gen_readme.py
```

Editing the Markdown by hand also works — the generator is a convenience, not a
gate — but the next run of the script will overwrite it.

CI checks the four versions stay parallel:

- same number of `##` sections in each file
- each file links to the other three
- every local path referenced (`assets/…`) actually exists

So when you add a section to `README.md`, add it to `README.fr.md`,
`README.ru.md` and `README.ua.md` too — otherwise `quality` goes red.

Run the same checks locally before pushing:

```bash
python .github/scripts/check_i18n.py
npx markdownlint-cli2
```

## Housekeeping

- `lychee.toml` excludes `github.com/DmytroPalahin/uvkit` while that repo is
  still private. Remove that line once it's public.
- The **Selected work** table is hand-picked on purpose (in `gen_readme.py`).
  Eight projects with one honest sentence each reads better than an
  auto-generated list of everything you've ever pushed.
- Three of those projects have no public repository yet (phishing detection,
  logistics optimization, reaction systems). They're the strongest entries on
  the list — pushing the code would do more for the profile than any workflow
  in this repo.
